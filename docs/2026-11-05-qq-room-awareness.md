# QQ 问房间时无法确认活动

现象：桌面聊天能说出当前动作，QQ 却回答没看到实时画面，并让主人确认接入。只读检查表明房间在线、动作已出门，世界位置在农场，QQ 同步本身无错误。

根因：桌面 `service.chat()` 自动组装房间事实；QQ 仅被提供 `room_world` 工具，未自动注入事实。模型把“能看到吗”理解为图像访问而没有查工具。工具存在和自动活动感知是两个不同环节。

取舍：修改机器人插件唤醒/最近消息模板可以补入信息，但会耦合独立插件与桥接源码，涉及已有其他改动及桥接重启。选择在独立插件里使用 DSH 已公开的 `agent/pre-step` 钩子，只匹配适配器确认的主人私聊 session id；保留其他机器人适配接口。

链路：UI 心跳 → 独立插件按角色保存状态 → DSH 主人 QQ 会话 pre-step → 追加有来源的冻结 UserMessage → QQ 现有模型与原人格/记忆正常回答。附带世界进度及最多八条、每条 200 字的最近桌面对话，仅作上下文，不重发桌面回复。

失败路径：房间 30 秒未更新则说明离线；读取失败注入明确未知说明；无法核对会话时不向任何不明会话补入私人信息，诊断字段给出下一步。拒绝的步骤、首步空消息和重复补入都保留原决定。活动感知不等于截图流。

验证：`npm test` 包含自动补入、精确会话匹配、跨会话隔离、离线/读取失败、UUID 与不可变消息格式、API 注册和干跑不冒充真实注入。另用实际当前人格、QQ 会话映射及房间文件只读干跑，不发送 QQ 消息。

生效：当前已运行的 DSH 未热重载改动，新 `/qq-context` 接口仍报告未知接口。需要重启 DSH 或真正重载该插件后，确认 `/status.qqContext.registered=true`，再让用户从 QQ 问一次。不得把离线干跑说成真实 QQ 会话已验证成功。

回滚：关闭 profile 的 `qqContext`，重载插件。配置备份在用户目录 `.dsh/room-world/install-backups/qq-context-20261105-190044/`；没有改机器人插件人格、记忆、桥接源码或清理历史。
